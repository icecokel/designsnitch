# Contributing to designsnitch

English | [Korean](./CONTRIBUTING.ko.md)

Bug reports, questions about the approach, and pull requests are all welcome. This page says what makes each of them easy to act on.

## Reporting a bug

Open an issue at <https://github.com/icecokel/designsnitch/issues> with:

- The designsnitch version (`npm ls designsnitch`) and the Tailwind CSS version.
- A small reproduction: the token CSS, `designsnitch.config.json`, and one source file are usually enough.
- What you ran (`designsnitch check`, `check --fix`, `eslint --fix`, the agent hook) and its output.
- What you expected, and what happened.

The most useful reports are about a wrong `replace`: a violation that `--fix` changed and the screen came out different. If you can, say how you saw the difference, for example the CSS Tailwind built before and after.

Do not include code or screenshots from a private codebase. Reduce the case to made-up values first.

## Development

Node.js 20.19 or later is required.

```sh
npm install
npm test
```

- Write the test first. A bug fix starts with a test that fails for the reported case.
- Tests are in `tests/` and run with vitest. `tests/temp-project.js` builds a throwaway project for end-to-end cases.
- Messages exist in English and Korean (`src/messages.js`). Add both.
- `README.md` is English and `README.ko.md` is Korean. A change in behavior updates both, and the skill in `skills/` that describes it.

## The rule for `replace`

`replace` is a promise: replacing `found` with the candidate keeps the screen and the behavior the same. `--fix`, `eslint --fix` and the agent hook act on it without asking a person.

So a change that makes more violations `replace` has to show that the promise holds, and "the value is the same" is not enough. Check what the build produces:

- The candidate exists after the build. A class has to be generated by Tailwind, and a `var()` has to point at a variable that is defined. A token declared outside `@theme` is a CSS variable with no class, and that case once turned backgrounds off.
- The computed value is the same: same color, same length in the same unit, and nothing else set along with it. A font size class can also set the line height.
- When that cannot be shown, the violation is `ask`, with a reason a person can read.

When in doubt, choose `ask`. A question costs a person a moment. A wrong `replace` changes a screen without anyone noticing.

## Commits and pull requests

- Commit titles follow `type(scope):summary` or `type:summary`, with no space after the colon. Types: `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `chore`, `ci`, `build`, `revert`.
- Keep the title within 50 characters, with no period at the end. The history is written in Korean. English titles are fine in a pull request.
- One change per pull request, with its tests. Say how you checked it, including anything you did not check.
- CI runs the tests on Node.js 20, 22 and 24 with ESLint 9 and 10. It has to pass.

## Scope

designsnitch is for React and Next.js projects that use Tailwind CSS and have no design system, or one that is not followed. It checks colors, shared components, radius and font size. Before starting on a new kind of check or a new framework, open an issue to talk about it first. `README.md` lists what is not supported and why.

## Releases

Maintainers release by pushing a version tag. Merging into `main` publishes nothing.
